## 행사철수 특수 처리 규칙

### 동작 요약
- **팀장 정산**: 기존과 동일 — 각 팀장이 자신의 행에 입력한 비고금액(note_amount) 그대로 본인 정산에 반영
- **업체 청구(정산서)**: 같은 날짜·같은 업체·품목="행사철수" 그룹은 행별로 합산되지 않고 **1건만 등록**하되, 그 1건의 금액 = 해당 날짜·업체의 모든 팀장 행의 비고금액 합계
  - 즉, 입력은 팀장별로 N행 들어가지만 업체 청구서에는 1행으로 보임 (금액은 N행 비고금액의 합)
  - 수도권/지방 배송비는 0으로 처리 (행사철수는 비고금액만 청구)

### 식별 방법
- `item` 필드(품목)가 정확히 `"행사철수"`인 행을 특수일로 인식
  (사용자가 추후 다른 키워드 추가 원하면 상수만 확장)

### 변경 파일

**1. `src/lib/statementData.ts`** (업체 청구 집계 로직)
- 회사별 행 집계 시 `(date, company_id)` 기준으로 `item === "행사철수"` 행들을 그룹핑
- 각 그룹을 1건의 가상 행으로 합치되:
  - `metro_fee` = 0
  - `regional_fee` = 0
  - `note_amount` = 그룹 내 모든 행의 `note_amount` 합
  - `customer_name` = "행사철수" (또는 첫 행 값)
  - 팀장 정보는 표시용으로 첫 행 기준 (이미 별도 정산에서 처리됨)
- 팀장 정산 데이터 흐름(`leaderDeductions`, `allocateRow`)은 **변경 없음** — 행별 원본 그대로 사용

**2. `src/lib/statementData.test.ts`** (테스트 추가)
- 같은 날짜·업체에 행사철수 3행(비고 10,000/15,000/20,000)이 있을 때:
  - 업체 청구에 행사철수가 1행만 나타나고 금액 = 45,000
  - 팀장 정산은 각 팀장이 본인 금액 그대로 받음

**3. UI 표시**
- `Records.tsx`, `CompanySettlement.tsx`에서 행사철수 행에 작은 배지 "1회 청구" 표시(선택)

### 안전 장치
- 행사철수 행에 수도권/지방 배송비가 입력되어 있어도 업체 청구 시 무시 (경고 issue 추가)
- 팀장 정산 합계 vs 업체 청구 합계 비교 검증(`validateRow`/`comparePeriodTotals`)에서 행사철수는 예외 처리하여 "불일치" 오탐 방지

### 영향 없는 부분
- 데이터베이스 스키마 (변경 없음)
- 팀장 정산 계산식 (강형주/신동석 1/2분배, 3분할, settle_to_id 등 모든 기존 규칙 유지)
- 입력 화면 — 사용자는 평소처럼 팀장별로 행 추가
